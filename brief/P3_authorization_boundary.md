# P3 授权边界与停止条件

版本：V1.0-RC1 配套草案。日期：2026-10-12。状态：**待评审**。本文描述必须实现的边界及拟议细节，不证明当前代码已经具备这些能力，也不构成对任何目标的实际测试授权。

需求依据：[Specification](P3_specification_v1.0-rc1.md)，特别是 P3-REQ-002、007～012、015～017。安全不变量沿用 [Problem Frame](P3_problem_frame.md) 的 INV-01～05，不另设冲突版本。

## 1. 授权对象与两层权限

只允许项目负责人批准的本地隔离模拟 HTTP JSON API、模拟 Bearer Token 身份和只读操作。测试人员提供接口契约和预期权限矩阵，授权维护者确认可发送范围。

Controller 判断是否允许发送；API 的业务权限是否正确由响应证据和权限矩阵判断。批准模拟跨用户／跨角色请求，是批准执行负向检查，不能改变 API 本应拒绝的业务规则。

## 2. 授权配置最小内容（拟议契约）

| 配置内容 | 必须约束的信息 |
| --- | --- |
| 标识与来源 | authorization_id、版本、批准者标识、批准范围说明、有效状态及有效期（如配置）。缺失必要信息即拒绝启动。 |
| 目标 | 精确 scheme、host、port；仅经确认的本地模拟服务。RC1 建议使用回环 IP 字面量，部署方案待评审。 |
| 请求范围 | 已批准的 endpoint_id、路径模板、HTTP 方法、路径／查询参数名及允许值、允许请求头；首版建议 GET，无请求体。 |
| 身份与对象 | identity_ref（或明确的 anonymous）、模拟凭据引用、角色、对象 ID 及归属；允许的身份与端点／对象组合须显式列出。 |
| 检查范围 | check_id、检查类型、策略可选择的候选集合；不得自行探测未列出的端点或资源。 |
| 预算 | max_checks=8、logical_timeout_seconds=90、concurrency=1，均为待评审试跑值。 |
| 停止控制 | Controller 可读取的撤权信号和授权状态；具体本地信号实现待评审。 |
| 证据设置 | 输出位置、脱敏规则、单条响应记录上限；具体上限待评审，截断须标记。 |

配置由可信入口加载并绑定本次运行。运行中允许撤权，不允许扩大范围；需要扩大时终止原运行，重新批准配置并创建新运行。Planner 不得持有或修改 Controller 的可写政策引用；同进程设计不提供对任意恶意 Python 代码的隔离保证。

## 3. 每次派发前的强制检查

Controller 必须依次验证：意图格式和类型 → 授权有效且未撤权 → 目标与端点 → 方法及只读性质 → 身份、对象和参数组合 → 预算和并发 → 记录授权决定 → 派发。

- 缺字段、未知字段、错误类型、非法枚举、歧义路径或越界参数均拒绝，保存原因；不得仅验证 target 和 tool。
- 执行器只能接受通过该入口的请求；Planner 不直接发送 HTTP，不把原始 Token 放入意图或日志。
- 拟议首版仅允许契约明确无业务写入副作用的 GET。服务端安全日志等运维记录不视为业务写入。
- 不自动跟随重定向，不利用代理改变目标，不解析响应中提供的 URL 作为新目标。无法确认实际目的地址在本地批准范围时拒绝。
- 执行时使用已验证的同一份规范化请求，禁止验证后替换目标、凭据引用或参数。最终撤权／预算检查与派发须串行协调。

## 4. 预算与停止

参数和计数口径均待老师评审，统一采用 Specification 第 4 节：

- 一项检查是一个确定身份、端点、参数和预期的候选，最多派发一次请求。合法访问对照也是独立检查。
- Controller 在接纳检查尝试前检查剩余名额并预留一项，包含随后被拒绝的尝试；同一尝试不重复计数，第 8 项可执行，第 9 次提交只记录预算拒绝，不接纳或派发。首版不自动重试。计划超过 8 项时拒绝启动，不静默裁剪；候选集合可更多，但单次计划不得超过上限。
- 运行进入 RUNNING 时启动可注入、单调递增的逻辑时钟；规划、校验、HTTP 等待和证据处理的运行耗时计入预算，实际运行不得暂停计时。90 秒到达后不派发新请求，当前请求应超时或取消；请求超时不得超过剩余预算。最终停止报告可在预算外收尾，但不再发请求。
- 已完成全部计划则 COMPLETED；还有未完成检查而达到预算则 STOPPED/BUDGET_EXHAUSTED。拒绝也消耗预算，不能靠不断生成非法提案逃避上限。
- 撤权生效后不得派发新请求；尝试取消在途请求并记录结果。已发送请求不能撤回，不得声称零在途请求。停止后到达的响应可留作附加证据，但不得据此将该未完成检查改为 PASS。
- 授权失效、预算耗尽、撤权、无法可靠保存审计记录或运行时异常都进入停止路径，不自动扩大授权或重新启动。具体条件和原因码以 Specification 第 7 节为准。

## 5. 停止后的报告

保留停止前已完成用例的有据结论；被拒绝、未派发、超时或证据不足的检查为 INCONCLUSIVE，分别记录原因。报告必须列出计划数、尝试数、实际请求数、完成数、未完成项、停止原因和证据缺口。

运行正常结束不等于所有检查通过；某检查被拒绝也不能证明被测 API 正确拒绝。证据写入失败时停止派发，并通过可用的错误输出说明失败；不能承诺在存储不可用时仍生成完整证据文件。
