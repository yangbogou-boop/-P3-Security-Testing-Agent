# P3 问题边界与目标定义（Problem Frame）

项目名称：**面向软件验收阶段的黑盒授权安全测试 Agent**。

更新日期：2026-10-12。状态：需求定位已由项目负责人确定；已确定的工程方向由负责人负责；新推荐方案待负责人确认，正式课程契约／目录及班级预算依有据教师门槛办理，不代表功能已实现或验收通过。

## 1. 用户、场景与问题

主要用户是软件测试人员、验收人员，使用阶段是集成测试和交付前验收。用户需要在不获取被测系统源码的条件下，根据 HTTP JSON API 接口契约和预期权限矩阵，检查未认证访问、对象级访问控制及角色级访问控制，并取得可复核、范围有限的证据。

核心问题是：接口能返回响应，并不意味着认证和访问控制正确；手工切换用户、角色和资源容易遗漏检查条件，单纯记录状态码也不足以支持验收结论。系统应将经批准的检查计划、实际请求响应、预期权限及判定依据关联起来，明确已检查、未检查和证据不足的范围。

首版只在本地隔离模拟 API 上验证该流程。对模拟 API 的检查结果不能外推为真实系统或全部接口安全。

## 2. 两层权限与信任边界

1. **Agent 的执行授权**：Controller 根据项目授权配置，判断某个目标、端点、方法、测试身份和资源组合是否允许发送。未经批准的请求不得执行。
2. **被测 API 的业务权限**：依据测试人员提供的权限矩阵，判断 API 是否正确允许或拒绝访问。

例如，Controller 可以批准“模拟用户 A 读取模拟用户 B 的对象”的只读测试，而权限矩阵要求 API 拒绝该访问。API 正确拒绝可以使这一用例通过；Controller 拒绝发送则表示用例未完成，不能据此判定 API 安全。

系统同时防御自身越界：Planner 输出、API 响应及其中的自然语言均不能修改授权、扩大目标或解除预算。独立 Controller 保留最终否决权。V1 采用独立模块与强制执行入口，不宣称操作系统级或物理隔离。

## 3. V1.0 目标与非目标

### 必须交付的目标（尚待实现和验证）

- 在本地隔离模拟 HTTP JSON API 上执行未认证、对象级、角色级权限检查，包含合法访问对照。
- 根据接口契约和预期权限矩阵，以确定性规则生成有限检查计划。
- 所有请求经过不依赖 LLM 的 Controller 授权验证，再交由执行器发送。
- 管理检查数量、逻辑时间、串行执行和撤权停止；不清楚的授权默认拒绝。
- 记录允许、拒绝、异常和停止事件及脱敏证据，输出有限测试结论。
- 记录可比元数据，并在基础闭环后完成固定／动态比较及 ADR 取舍（REQ-021 MUST）；不预设动态更优，本轮没有实验结果。

### 首版非目标

- 任意公网、生产环境、网段扫描、自动发现未知目标或通用漏洞利用。
- 写操作；即使某种写操作以后获得批准，也需先变更首版只读规格。只读必须由接口契约确认，不能仅凭 HTTP 方法推断。
- 读取被测系统源码作为必要输入，或覆盖所有 API 安全风险。
- 图形界面、真实 LLM、真实云凭据、真实 LLM Token 成本证明。
- 进程／容器／物理隔离保证及针对任意同进程恶意代码的防护保证。

## 4. 安全不变量

以下是不允许被 Planner、策略或目标响应覆盖的 V1 需求，当前原型尚未证明全部成立：

| ID | 不变量 |
| --- | --- |
| INV-01 | Controller 否决优先：未经完整授权核验的请求不得发送。 |
| INV-02 | 授权不可由不可信数据扩大：目标响应、意图和错误反馈均不能修改政策或预算。 |
| INV-03 | 结论诚实：EXECUTED 不等于 PASS；证据不足、被阻断或未执行的用例为 INCONCLUSIVE。 |
| INV-04 | 撤权或预算到达停止条件后不得派发新请求；已发送请求不能被追溯撤销。 |
| INV-05 | 检查仅使用已批准的本地模拟目标、模拟身份和只读资源；证据不得泄露原始凭据。 |

## 6. 当前实现与差距

截至 2026-10-12 的源码静态核对：Planner 仅按关键词输出固定扫描意图；Controller 只检查硬编码目标和工具，并生成模拟成功结果；主程序演示两条路径。两层在同一进程内，Token 为公式模拟值。

尚未实现真实 HTTP 执行、本地模拟 API、三类权限检查、完整动作契约、预算、撤权、拒绝动作完整审计和有限结论。已有轨迹不构成这些能力的验收证据。本次只更新需求与设计文档，未运行系统或生成证据。
