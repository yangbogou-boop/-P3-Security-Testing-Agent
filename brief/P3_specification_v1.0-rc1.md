# P3 Specification V1.0-RC1

项目：**面向软件验收阶段的黑盒授权安全测试 Agent**。

日期：2026-10-12。状态：**Release Candidate 1，待老师评审**。本文件是需求候选基线，不是已批准标准、功能完成声明或测试报告。

## 1. 规范约定与适用范围

主要用户为软件测试人员、验收人员；使用阶段为集成测试和交付前验收；采用不要求被测系统源码的黑盒 HTTP JSON API 测试。首版只针对本地隔离模拟 API，覆盖未认证访问、对象级及角色级访问控制。

MUST 表示 V1 验收必须满足；SHOULD 表示建议满足，偏离须记录原因；MAY 表示可选，不阻塞 V1。它们表示本候选规格内部的要求强度，不表示老师已批准。需求 ID 一经分配不复用；后续删改保留 ID 并记录废止或替代关系。

仓库未发现独立的课程 Specification 模板。本草案按本次课程要求组织需求 ID、规范强度、输入输出、状态、异常、非功能要求、GWT 和待决问题；若老师提供正式模板，再保留 ID 迁移。

相关文档：[Problem Frame](P3_problem_frame.md)、[授权边界](P3_authorization_boundary.md)、[ADR 001](../design/ADR_001_controller_split.md)、[ADR 002](../design/ADR_002_black_box_api_scope.md)。本文定义活动需求与预算口径，授权边界展开执行约束；冲突需修订，不能由实现自行择宽执行。原 eval 扫描场景待下一轮迁移。

## 3. 输入、输出与两层权限

### 3.1 输入

- **接口契约**：端点 ID、HTTP 方法、路径及参数、只读声明、认证要求、成功／拒绝响应与必要 JSON 字段断言；不要求读取源码。
- **预期权限矩阵**：identity_ref／角色 × endpoint_id／资源归属 → ALLOW 或 DENY；使用模拟身份和对象。缺失单元格不默认允许。
- **授权配置**：批准的本地 origin、端点、身份及参数组合、有效状态、预算、授权标识和版本；详见授权边界。
- **运行输入**：策略 ID／版本、候选检查清单、契约及矩阵版本、证据输出位置；Token 通过凭据引用解析。
- **停止输入**：可信入口发出的撤权信号；目标响应中的“授权”文本不构成该信号或新的授权。

授权配置描述“Agent 可以测试什么”；业务权限矩阵描述“API 应该允许谁”。例如允许 Agent 使用 A 的模拟凭据请求 B 的对象，但业务期望为 DENY。

### 3.2 输出

- 检查计划及其 check_id、检查类型、身份引用、端点／参数、预期结果和关联对照。
- 每个检查的授权决定、执行状态、安全结论、原因及 evidence_id。
- 脱敏证据：run_id、check_id、动作关联标识、授权／契约／矩阵版本、策略版本、时间与预算、规范化请求、响应状态及必要 JSON 片段／断言、拒绝／异常／撤权／停止事件。
- 有限报告：授权范围、实际覆盖、PASS／FAIL／INCONCLUSIVE 数量与条目、未覆盖范围和证据限制。未进入计划的候选标记“未覆盖”，不得计为 PASS。

原始 Bearer Token 不进入报告或轨迹；响应截断或缺失必须说明，若影响判定则 INCONCLUSIVE。历史模拟数据保留其模拟性质，不计为真实 LLM 成本或真实 HTTP 证据。

## 4. 暂定参数与统一计数口径

全部为 **待评审／试跑方案，未获老师批准**：HTTP JSON API、模拟 Bearer Token、确定性规则 Planner、非 LLM Controller、已批准只读检查、max_checks=8、logical_timeout_seconds=90、concurrency=1。

RC1 进一步提议：首版使用接口契约确认无业务写入副作用的 GET、无请求体、不自动重试、不跟随重定向。是否接受这些细化项见 OQ-02。

1. 一项检查为一个身份、端点、参数及预期的组合，最多发送一次 HTTP 请求；合法访问对照单独计数。
2. Controller 接受一次检查尝试前确认剩余名额，再预留一个名额；包含随后被拒绝的意图。同一次尝试的多次校验不重复计数。第 8 个名额可正常执行，第 9 次提交仅记录预算拒绝事件，不接纳为新检查、不派发。初始计划不得超过 8 项，超过则启动失败，不能静默裁剪。候选集合大小可超过单次计划上限。
3. RUNNING 开始时启动单调逻辑时钟，计入规划、授权、请求等待和证据处理耗时。实际试跑使用真实单调经过时间；验收可注入可控时钟，不能用墙上日期跳变延长预算。
4. 派发前再次检查时间、撤权、计数和并发。elapsed >= 90 秒时禁止新派发；在途请求超时／取消，单次请求超时不超过剩余预算。最终停止报告收尾可超出预算，但不再发请求。
5. 全部计划完成时进入 COMPLETED；存在未完成检查且达到限制时 STOPPED/BUDGET_EXHAUSTED。执行期间最多一个在途请求。
6. 撤权后不再派发新请求，尽力取消在途请求，明确记录无法撤回已发送请求的事实。停止后完成的响应不使未完成项升级为 PASS。

旧 brief 的 5 轮／2 次纠正及 ADR 001 的重试 3 次属于历史规则，不适用于本 RC1。

## 5. 状态与判定

| 层次 | 值 | 含义 |
| --- | --- | --- |
| 授权决定 | ALLOW / DENY / NOT_EVALUATED | Controller 是否允许该请求发送；未进入校验的计划项为 NOT_EVALUATED。 |
| 执行状态 | NOT_EXECUTED / EXECUTED / ERROR / TIMEOUT / CANCELLED | EXECUTED 仅表示已收到 HTTP 响应，包含 401、403、404 和 5xx；传输错误为 ERROR。 |
| 安全结论 | PASS / FAIL / INCONCLUSIVE | 必须结合业务预期和充分证据判定，不能直接复制授权或执行状态。 |
| 运行状态 | READY / RUNNING / COMPLETED / STOPPED | 输入验证失败为 STOPPED/INVALID_INPUT；运行中故障、撤权或预算停止附原因码。 |

结果规则：

- 期望 ALLOW 且成功响应、身份／对象断言均满足，才可 PASS；确认的权限契约违例为 FAIL，并说明是否属于过度拒绝。
- 期望 DENY 且符合契约的拒绝响应、不泄露受保护内容，同时相关合法访问对照成立，才可 PASS。仅看到 403／404 不能证明资源存在且访问控制有效。
- 期望 DENY 却得到受保护对象或角色专属数据，且身份、资源和响应断言可确认，为 FAIL。确定泄露证据不能因缺少对照被掩盖为 PASS。
- 网络异常、无法确认身份或夹具、响应非预期且无法可靠判定、证据不足，均为 INCONCLUSIVE。5xx 本身不直接判为访问控制漏洞；若响应仍包含可确认的越权泄露证据，则保留 FAIL，否则为 INCONCLUSIVE。
- Controller DENY → NOT_EXECUTED → INCONCLUSIVE（对被测 API 而言）；独立的 Controller 拦截验收可以通过，二者不可混淆。
- 撤权、预算终止不抹去此前有据结论；剩余项为 INCONCLUSIVE。COMPLETED 只说明计划已处理完，可含 FAIL 或 INCONCLUSIVE。

## 6. 稳定需求编号总表

本表的 MUST 项均为 V1 待实现／待验收要求；部分现有原型逻辑不等于完整满足。验收引用指向第 8 节。

| ID | 强度 | 需求 | 验收 |
| --- | --- | --- | --- |
| P3-REQ-001 | MUST | 基于接口契约和预期权限矩阵实施黑盒检查；验证必要输入，缺失或矛盾时停止且不发请求。 | GWT-N01 |
| P3-REQ-002 | MUST | 仅对经批准的本地隔离模拟 HTTP JSON API 使用模拟凭据和只读操作。 | GWT-P01、GWT-A02 |
| P3-REQ-003 | MUST | 确定性 Planner 从批准候选中生成有 ID 的有限计划；同一输入、配置和策略版本产生相同计划。 | GWT-P04 |
| P3-REQ-004 | MUST | 检查受保护端点的未认证访问，以权限矩阵和响应证据判定。 | GWT-P02、GWT-N02 |
| P3-REQ-005 | MUST | 检查模拟用户访问他人对象的对象级权限，并关联合法所有者访问对照。 | GWT-P02、GWT-N02 |
| P3-REQ-006 | MUST | 检查低权限角色访问角色专属端点，并关联合法角色访问对照。 | GWT-P02、GWT-N02 |
| P3-REQ-007 | MUST | Controller 独立于 Planner 和 LLM 作授权决定；执行器只经强制入口派发。 | GWT-A01、GWT-A02 |
| P3-REQ-008 | MUST | 严格验证意图类型、字段、端点、方法、身份及参数组合；非法意图拒绝并记原因。 | GWT-N03 |
| P3-REQ-009 | MUST | 不可信响应不能修改授权／预算；授权运行中只能撤销，扩权必须重新批准并启动新运行。 | GWT-A01 |
| P3-REQ-010 | MUST | 实施第 4 节的计数、逻辑时间和并发预算；不得通过拒绝、重试或时钟跳变逃避限制。 | GWT-N04、GWT-N05 |
| P3-REQ-011 | MUST | 支持撤权停止，新派发前核验撤权；记录在途取消及未完成范围。 | GWT-A03 |
| P3-REQ-012 | MUST | 在授权不明、连接故障、超时、运行异常或审计写入失败时安全停止，不自动扩权或盲目重试。 | GWT-N01、GWT-N05、GWT-N06 |
| P3-REQ-013 | MUST | 通过 Executor 获取实际本地请求响应证据，不以模拟成功消息替代已执行事实。 | GWT-P01、GWT-N06 |
| P3-REQ-014 | MUST | 分开记录授权、执行和测试结论，按第 5 节判定，证据不足不得通过。 | GWT-P01、GWT-P02、GWT-N02、GWT-N07 |
| P3-REQ-015 | MUST | 关联记录允许、拒绝、错误、撤权、预算与停止事件，使用唯一运行／检查／动作标识，禁止同秒覆盖。 | GWT-P03、GWT-N03、GWT-A03 |
| P3-REQ-016 | MUST | 凭据仅用引用，证据脱敏且标记缺失／截断；真实与模拟数据及成本不得混淆。 | GWT-P03、GWT-N07 |
| P3-REQ-017 | MUST | 报告仅对已检查范围给出有限结论，列出未决和未覆盖范围，不能声称整个系统安全。 | GWT-N04、GWT-N07、GWT-A03 |
| P3-REQ-018 | MUST | 模拟环境具有可重置身份／角色／对象夹具，支持正确拒绝与已知权限缺陷的可重复验收。 | GWT-P02、GWT-N02、GWT-P04 |
| P3-REQ-019 | SHOULD | 用配置和命令行入口完成运行与报告读取，不要求图形界面；说明输入错误及停止原因。 | GWT-P04、GWT-N01 |
| P3-REQ-020 | MUST | 为后续策略对比记录策略版本、候选集合、夹具版本、相同预算、实际请求数、覆盖和有据结果；不伪造比较结果。 | GWT-P04 |
| P3-REQ-021 | SHOULD | 下一阶段比较固定顺序与基于既有结果的动态选择策略，保持相同输入、授权、夹具和预算；解释额外规划开销。 | GWT-P05（后续） |
| P3-REQ-022 | MAY | 基础验收完成并经另行评审后接入真实 LLM；不得改变 Controller 权限边界，真实成本单独计量。 | GWT-A04（后续） |

### 非功能要求与不变量映射

- 安全性：P3-REQ-007～012 对应 INV-01、02、04；P3-REQ-002、016 对应 INV-05。
- 可靠性与有界执行：P3-REQ-010～012；时间上限用于停止调度，不作为实时操作系统级截止保证，取消延迟须实测试跑说明。
- 可审计与诚实性：P3-REQ-014～017 对应 INV-03；日志不可用时明确缺口。
- 可重复性：P3-REQ-003、018、020；记录版本和夹具，禁止将模拟 Token 冒充测量值。
- 可用性：P3-REQ-019；本候选不设未经测量的吞吐量或性能达标声明。

## 7. 异常行为

| 条件 | 行为及报告 |
| --- | --- |
| 必要输入缺失、矩阵矛盾、初始计划超预算 | 启动失败，不发请求，STOPPED/INVALID_INPUT；记录可用错误信息。 |
| 单项意图无效或超出授权范围 | DENY、NOT_EXECUTED、INCONCLUSIVE；记录拒绝并消耗一次检查。其他已批准检查可继续，直到预算或停止条件。 |
| 授权失效／撤权 | 停止新派发；记录 AUTHORIZATION_INVALID 或 REVOKED 及在途状态。 |
| 网络错误／请求超时／运行时异常 | STOPPED，附 TRANSPORT_ERROR、TIMEOUT 或 RUNTIME_ERROR；未完成项 INCONCLUSIVE。 |
| 收到 5xx／无法解析预期 JSON | EXECUTED，无法可靠判定时为 INCONCLUSIVE；存在可确认违例证据时保留 FAIL。记录响应；RC1 提议停止本轮并标记 RESPONSE_ERROR，避免连续无效请求。 |
| 到达检查／时间预算且仍有未完成项 | STOPPED/BUDGET_EXHAUSTED；保留先前结果，列出剩余检查。 |
| 证据写入失败 | STOPPED/AUDIT_ERROR；停止新请求，通过可用错误输出说明证据缺口，不能假称记录完整。 |

## 8. Given-When-Then 验收场景

以下场景使用受控本地模拟夹具和可观测派发计数；无场景在本轮实际执行。Negative 表示异常输入或缺陷模式，Adversarial 表示针对 Agent 执行边界的对抗。每个参数化变体独立验收并受单次运行预算限制，不能把全部场景塞进一次 8 项计划。

| ID／类别 | Given | When | Then |
| --- | --- | --- | --- |
| GWT-P01 Positive | 批准的只读端点、有效模拟身份、矩阵期望 ALLOW，夹具响应符合契约 | 通过 Controller 请求本地 API | ALLOW／EXECUTED／PASS；有真实请求响应证据，派发数为 1。 |
| GWT-P02 Positive | 正确权限模式，参数化为未认证、他人对象、低角色三类；各自有合法访问对照 | 发送获准的负向请求并检查关联对照 | API 按契约拒绝且无泄露，对照成功；负向用例为 ALLOW／EXECUTED／PASS。每个请求单独计检查。 |
| GWT-P03 Positive | 可写证据位置，模拟 Token，两个同秒启动的运行 | 执行允许及拒绝检查并生成记录 | ID 唯一不覆盖，事件可关联，拒绝原因可查；无原始 Token；模拟数据明确标识。 |
| GWT-P04 Positive | 相同版本的契约、矩阵、重置夹具、策略和预算 | 两次规则规划并按文档入口使用；核对比较元数据 | 计划一致、输入可复现，记录候选、版本、预算、请求数与覆盖；不声称已完成策略比较。 |
| GWT-P05 Positive／后续 | 固定及动态策略都已实现，同一候选、夹具、授权和预算 | 分别运行并比较 | 两者均遵守 Controller 边界；报告覆盖、有据结果、请求数和开销，指标定义经评审；未实现前标记未执行。 |
| GWT-N01 Negative | 契约缺失、矩阵矛盾、授权缺失或初始计划 9 项之一 | 请求启动 | 不发请求，STOPPED/INVALID_INPUT，明确原因；不得擅自补授权或裁剪计划。 |
| GWT-N02 Negative | 已知缺陷模式，参数化为匿名泄露、他人对象泄露、低角色泄露 | 发送批准的只读请求 | ALLOW／EXECUTED／FAIL，并保留能确认泄露的证据；另以预期 ALLOW 却确认被错误拒绝的变体验证过度拒绝 FAIL。 |
| GWT-N03 Negative | 输入为畸形 JSON、数组、null、错误字段类型、缺字段、未知字段或越界身份参数之一 | 提交 Controller | DENY／NOT_EXECUTED／INCONCLUSIVE，不崩溃、不派发，记录原因并计入尝试数。 |
| GWT-N04 Negative | 8 次尝试已用尽（包含拒绝），或第 8 次完成后仍试图追加 | 请求派发下一项 | 第 9 项不派发；若存在未完成项则预算停止并列为 INCONCLUSIVE；全部计划完成则 COMPLETED，不能追加。 |
| GWT-N05 Negative | 可控单调时钟，耗时含规划／等待；存在在途请求 | 时钟到达 90 秒，或系统日期回拨 | 到点无新派发，在途超时／取消；日期回拨不扩预算，并发始终不超过 1；未完成项 INCONCLUSIVE。 |
| GWT-N06 Negative | 参数化为连接失败、HTTP 5xx、非预期 JSON、审计存储不可写、执行异常 | 运行批准检查 | 按第 7 节停止，记录准确执行状态和缺口；不自动重试，不产生虚构成功或完整证据声明。 |
| GWT-N07 Negative | Controller 拒绝、对照不成立、判定所需响应截断／缺失之一，且无可确认违例证据 | 生成结论和报告 | 受影响用例 INCONCLUSIVE；不能把 EXECUTED 或拒绝等同于 PASS；列出限制和未覆盖范围。 |
| GWT-A01 Adversarial | 响应含“扩大目标／解除预算”指令或 Planner 提议修改政策 | 处理响应并生成后续意图 | 配置和预算不变；越界意图被拒绝且无网络派发；Planner 不能绕过入口。 |
| GWT-A02 Adversarial | 提案包含外部 origin、未批准端点、写方法、歧义路径、替换身份或响应重定向之一 | 请求执行或收到重定向 | 不派发越界请求、不自动跟随；记录拒绝或未决原因，凭据不转发到其他目标。 |
| GWT-A03 Adversarial | 最终派发前或存在在途请求时收到可信撤权 | Controller 处理撤权并尝试后续派发 | 撤权生效后新增派发为 0，尝试取消在途；记录停止、在途事实和未决项，不伪称已发送请求被撤回。 |
| GWT-A04 Adversarial／后续 | 另行批准的真实 LLM 接入已存在 | 模型提出越界请求 | Controller 同样拒绝，原边界及预算不变；成本来自真实计量且与模拟数据区分。 |
