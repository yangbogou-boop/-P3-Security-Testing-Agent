# P3 Specification V1.0-RC2

项目：**面向软件验收阶段的黑盒授权安全测试 Agent**。

日期：2026-10-14。状态：**Release Candidate 2，工程修订待项目负责人审核；正式课程契约与班级预算尚未取得教师批准／冻结记录**。本文件是需求候选基线，不是已批准标准、功能完成声明或测试报告。

当前候选入口为本 RC2，承接第三轮工程治理修订及本轮三个审核意见。[RC1 历史快照](P3_specification_v1.0-rc1.md) 原样保留，包含前三轮版本记录；其中旧的要求强度及当前性措辞只用于历史追踪，活动要求以本 RC2 为准。需求 ID 不重新编号。

## 1. 规范约定与适用范围

主要用户为软件测试人员、验收人员；使用阶段为集成测试和交付前验收；采用不要求被测系统源码的黑盒 HTTP JSON API 测试。首版只针对本地隔离模拟 API，覆盖未认证访问、对象级及角色级访问控制。

MUST 表示 V1 验收必须满足；SHOULD 表示建议满足，偏离须记录原因；MAY 表示可选，不阻塞 V1。它们表示本候选规格的工程要求强度，不表示功能已完成或正式教学契约已获批准。教师门槛须有课程原文依据，其余由项目负责人决策；重要取舍记录 ADR。需求 ID 一经分配不复用；后续删改保留 ID 并记录废止或替代关系。

已核对用户提供的四份课程 PPT；独立正式 Specification 模板及本项目批准契约尚未取得，额外模板审批要求标为“课程依据待核实”。现有结构保留 ID、规范强度、输入输出、状态、异常、非功能要求及 GWT；取得正式模板后保留 ID 对齐，不把其他项目示例当成 P3 强制要求。依据和 A/B/C 分类见 [决策治理登记](P3_decision_governance.md)。

相关文档：[Problem Frame](P3_problem_frame.md)、[授权边界](P3_authorization_boundary.md)、[ADR 001](../design/ADR_001_controller_split.md)、[ADR 002](../design/ADR_002_black_box_api_scope.md)。本文定义活动需求与预算口径，授权边界展开执行约束；冲突需修订，不能由实现自行择宽执行。配套 [eval GWT](../eval/P3_GWT_scenarios.md) 已按本轮修订同步，均待执行。

## 3. 输入、输出与两层权限

### 3.1 输入

- **接口契约**：端点 ID、HTTP 方法、路径及参数、只读声明、认证要求、成功／拒绝响应与必要 JSON 字段断言；不要求读取源码。
- **预期权限矩阵**：identity_ref／角色 × endpoint_id／资源归属 → ALLOW 或 DENY；使用模拟身份和对象。缺失单元格不默认允许。
- **授权配置**：批准的本地 origin、端点、身份及参数组合、有效状态、预算、授权标识和版本；详见授权边界。
- **运行输入**：策略 ID／版本、候选检查清单、契约及矩阵版本、证据输出位置；Token 通过凭据引用解析。
- **停止输入**：可信入口发出的撤权信号；目标响应中的“授权”文本不构成该信号或新的授权。

授权配置描述“Agent 可以测试什么”；业务权限矩阵描述“API 应该允许谁”。例如允许 Agent 使用 A 的模拟凭据请求 B 的对象，但业务期望为 DENY。

### 3.2 输出

- 检查计划及其 check_id、检查类型、身份引用、端点／参数、预期结果和关联对照。
- 每个检查的授权决定、执行状态、安全结论、原因及 evidence_id。
- 脱敏证据：run_id、check_id、动作关联标识、授权／契约／矩阵版本、策略版本、时间与预算、规范化请求、响应状态及必要 JSON 片段／断言、拒绝／异常／撤权／停止事件。
- 有限报告：授权范围、实际覆盖、PASS／FAIL／INCONCLUSIVE 数量与条目、未覆盖范围和证据限制。未进入计划的候选标记“未覆盖”，不得计为 PASS。

原始 Bearer Token 不进入报告或轨迹；响应截断或缺失必须说明，若影响判定则 INCONCLUSIVE。历史模拟数据保留其模拟性质，不计为真实 LLM 成本或真实 HTTP 证据。

## 4. 暂定参数与统一计数口径

已由项目负责人确定的工程方向：HTTP JSON API、模拟 Bearer Token、确定性规则 Planner、非 LLM Controller、只读检查。当前数字 **max_checks=8、logical_timeout_seconds=90、concurrency=1 为课程示例试跑值**；S3 第 40 张／稿034要求教师试跑后冻结本班预算，尚未获得冻结记录。技术选型不是统一等待教师审批；具体执行范围必须同时取得课程目录批准与目标所有者／授权负责人许可。配置和计数以下以当前试跑值说明，最终数字按批准冻结版本替换。

此前已审核的 RC1 工程口径：首版使用契约确认无业务写入副作用的 GET、无请求体、不自动重试、不跟随重定向；OQ-02 为 B 类已确认事项。计数与停止语义属于负责人决策，数字预算的试跑与班级冻结分别属于 C-01／A-02。

1. 一项检查为一个身份、端点、参数及预期的组合，最多发送一次 HTTP 请求；合法访问对照单独计数。候选集合可超过 8 项；单次运行的累计登记检查不得超过 8 项。
2. **计时起点**：可信入口完成必要输入／授权配置的静态预检后、首次调用 Planner 前，记录一次单调时刻 t0 并进入 RUNNING。初始规划、计划校验／登记、后续选择或追加规划、授权校验、请求等待、判定及运行中证据处理全部计时。外部准备夹具及静态预检不计时；预检不得调用 Planner、生成计划或发送请求。初始规划失败仍保留 t0 和耗时。实际试跑使用真实单调经过时间；验收可注入可控时钟，墙上日期跳变不能延长预算，不得暂停或重置 t0。
3. **初始计划与追加**：初始计划生成后先校验整体结构、唯一 check_id 和项数；超过 8 项则 STOPPED/INVALID_INPUT，不派发、不裁剪。登记初始计划时占用计划名额，但不增加尝试数。RUNNING 中可以提交追加提案；Controller 在执行前登记，初始与追加共用同一累计 8 项额度。已有名额不得删除、替换、回收或重置；基础闭环可先固定策略；完整工程交付还须完成 REQ-021 的动态选择比较与取舍。
4. **计数**：plan_count 为累计已登记检查数；attempt_count 为 Controller 接纳并开始校验的尝试数；request_count 为实际已派发 HTTP 请求数。对已登记检查接纳首次尝试时 attempt_count 加 1，不能再次占用计划名额；随后授权拒绝仍消耗该次尝试，最多派发一次。同次尝试的多次校验不重复计数。未登记提案（含畸形意图）必须先获分配一个 Controller 侧名额／关联标识；拒绝后保留该名额和记录，不能因无有效 check_id 漏计。相同已处理检查的重复提交只记录拒绝事件，不重试、不派发、不新增名额；改换 ID 的新提案按追加计数。始终满足 request_count <= attempt_count <= plan_count <= 8；已登记但未尝试的检查不计入 attempt_count。
5. **追加超限**：RUNNING 时累计已登记 8 项，再提交新提案，只记录预算拒绝事件，不登记第 9 项、不增加尝试数、不派发，并进入 STOPPED/BUDGET_EXHAUSTED。记录被拒追加提案与剩余范围；已登记未完成项为 INCONCLUSIVE，未登记候选及被拒追加项列为未覆盖，不能冒充已检查项。第 8 项在其他条件允许时可正常执行。
6. **调度与结束**：Controller 串行处理检查、追加提案及停止事件，每次响应处理后先处理该轮待决追加，再判断完成。所有已登记检查均处理结束且无待决追加、无停止原因时，才进入 COMPLETED；单项授权拒绝也是处理结束，可带 INCONCLUSIVE。COMPLETED 和 STOPPED 都是不可重开的终态，终态后的追加仅记录拒绝事件，不改变原状态、计数或结果；新运行必须重新校验授权，不得自动重启。
7. **时间边界与状态优先**：每次接纳、派发及完成判定前核验撤权／授权、运行错误及 elapsed = now - t0。elapsed >= 90 秒即 STOPPED/BUDGET_EXHAUSTED，禁止新派发；即使此时刚处理完最后一项，也不得改为 COMPLETED。若最后一项在 90 秒前处理完且无待决追加，则 COMPLETED，包括正好处理完第 8 项的情况。请求超时不超过剩余预算，在途到点应超时／取消，并发始终不超过 1。相同检查点同时出现多个停止条件时：REVOKED 优先于 AUTHORIZATION_INVALID，其次运行错误，再次预算耗尽；全部条件均记录，时间预算触发时优先于单请求 TIMEOUT 原因。最终停止报告可在预算外收尾，但不再发请求。
8. 撤权后不再派发新请求，尽力取消在途请求，明确记录无法撤回已发送请求的事实。停止后完成的响应可作为附加证据，不使未完成项升级为 PASS。
9. **无新增证据只限制无价值循环**：仅在 RUNNING 中请求继续重复规划／继续循环、该循环没有新增有效证据，并且核对整个批准计划与候选后确认没有尚未执行且具有预期证据价值的检查或必要合法访问对照、也无在途检查待处理时，才可 STOPPED/NO_NEW_EVIDENCE。记录重复提案、已核对的剩余检查／对照及停止理由，不以 Planner 未提出下一项代替核对。一次未发现漏洞、返回符合契约的拒绝、与别的身份／对象得到相同状态码，均不能单独触发此原因；它们仍可能提供新的覆盖或对照证据。只要存在上述有价值的批准检查且授权／预算等允许，应继续处理，不得跳过；无法判断其价值时不能直接宣告无价值。全部计划已处理且无待决追加时，仍按第 6 项正常 COMPLETED，不强行改成 NO_NEW_EVIDENCE；撤权、预算及其他停止条件按原规则优先处理，本项不延长预算或放宽权限。课程依据见 S3 第 40 张／稿034及112／附录B3。

旧 brief 的 5 轮／2 次纠正及 ADR 001 的重试 3 次属于历史规则，不适用于本 RC2。

## 5. 状态与判定

| 层次 | 值 | 含义 |
| --- | --- | --- |
| 授权决定 | ALLOW / DENY / NOT_EVALUATED | Controller 是否允许该请求发送；未进入校验的计划项为 NOT_EVALUATED。 |
| 执行状态 | NOT_EXECUTED / EXECUTED / ERROR / TIMEOUT / CANCELLED | EXECUTED 仅表示已收到 HTTP 响应，包含 401、403、404 和 5xx；传输错误为 ERROR。 |
| 安全结论 | PASS / FAIL / INCONCLUSIVE | 必须结合业务预期和充分证据判定，不能直接复制授权或执行状态。 |
| 运行状态 | READY / RUNNING / COMPLETED / STOPPED | 预检或初始计划校验失败为 STOPPED/INVALID_INPUT；运行中故障、撤权或预算停止附原因码；终态不得通过追加重开。 |

结果规则：

- 期望 ALLOW 且成功响应、身份／对象断言均满足，才可 PASS；确认的权限契约违例为 FAIL，并说明是否属于过度拒绝。
- 期望 DENY 且符合契约的拒绝响应、不泄露受保护内容，同时相关合法访问对照成立，才可 PASS。仅看到 403／404 不能证明资源存在且访问控制有效。
- 期望 DENY 却得到受保护对象或角色专属数据，且身份、资源和响应断言可确认，为 FAIL。确定泄露证据不能因缺少对照被掩盖为 PASS。
- 网络异常、无法确认身份或夹具、响应非预期且无法可靠判定、证据不足，均为 INCONCLUSIVE。5xx 本身不直接判为访问控制漏洞；若响应仍包含可确认的越权泄露证据，则保留 FAIL，否则为 INCONCLUSIVE。
- Controller DENY → NOT_EXECUTED → INCONCLUSIVE（对被测 API 而言）；独立的 Controller 拦截验收可以通过，二者不可混淆。
- 撤权、预算终止不抹去此前有据结论；剩余项为 INCONCLUSIVE。COMPLETED 只说明计划已处理完，可含 FAIL 或 INCONCLUSIVE。

| P3-REQ-021 | MUST | 基础闭环后比较固定顺序与基于既有结果的确定性动态选择策略，采用相同输入、声明目标、授权、重置夹具及预算；报告覆盖、检出、误确认、未确定、工具故障、越界动作、成本和规划开销，并以 ADR 记录采用／限制采用／保留固定／需要更多证据。依据 S3 37、42、46、73、99 的课程任务映射，不预设动态更优。 | GWT-P05 |
| P3-REQ-022 | MAY | 基础验收后经负责人另行决策、满足数据与成本授权后可接入真实 LLM；不得改变 Controller 权限边界，真实成本单独计量。 | GWT-A04（后续） |

### 非功能要求与不变量映射

- 安全性：P3-REQ-007～012 对应 INV-01、02、04；P3-REQ-002、016 对应 INV-05。
- 可靠性与有界执行：P3-REQ-010～012；时间上限用于停止调度，不作为实时操作系统级截止保证，取消延迟须实测试跑说明。
- 可审计与诚实性：P3-REQ-014～017 对应 INV-03；日志不可用时明确缺口。
- 可重复性：P3-REQ-003、018、020；记录版本和夹具，禁止将模拟 Token 冒充测量值。
- 可用性：P3-REQ-019；本候选不设未经测量的吞吐量或性能达标声明。

## 7. 异常行为

| 条件 | 行为及报告 |
| --- | --- |
| 必要输入缺失、矩阵矛盾、初始计划超预算 | 启动失败，不发请求，STOPPED/INVALID_INPUT；记录可用错误信息。 |
| 单项意图无效或超出授权范围 | DENY、NOT_EXECUTED、INCONCLUSIVE；记录拒绝并消耗一次检查。其他已批准检查可继续，直到预算或停止条件。 |
| 授权失效／撤权 | 停止新派发；记录 AUTHORIZATION_INVALID 或 REVOKED 及在途状态。 |
| 网络错误／请求超时／运行时异常 | STOPPED，附 TRANSPORT_ERROR、TIMEOUT 或 RUNTIME_ERROR；未完成项 INCONCLUSIVE。 |
| 收到 5xx／无法解析预期 JSON | EXECUTED，无法可靠判定时为 INCONCLUSIVE；存在可确认违例证据时保留 FAIL。记录响应；沿用 RC1 的停止口径，标记 RESPONSE_ERROR，避免连续无效请求。 |
| RUNNING 中追加超过累计 8 项，或 elapsed >= 90 秒 | STOPPED/BUDGET_EXHAUSTED；保留先前结果，已登记未完成项 INCONCLUSIVE，被拒追加项及未选候选列为未覆盖；按第 4 节处理终态与并发停止原因。 |
| 证据写入失败 | STOPPED/AUDIT_ERROR；停止新请求，通过可用错误输出说明证据缺口，不能假称记录完整。 |
| 满足第 4 节第 9 项全部条件的无价值重复规划／继续循环 | STOPPED/NO_NEW_EVIDENCE；保留有据结论并列未覆盖。一次未发现漏洞不是停止依据；尚有有价值的批准检查、必要对照或在途结果时不得据此提前停止。 |

## 8. Given-When-Then 验收场景

以下场景使用受控本地模拟夹具和可观测派发计数；无场景在本轮实际执行。Negative 表示异常输入或缺陷模式，Adversarial 表示针对 Agent 执行边界的对抗。每个参数化变体独立验收并受单次运行预算限制，不能把全部场景塞进一次 8 项计划。

| ID／类别 | Given | When | Then |
| --- | --- | --- | --- |
| GWT-P01 Positive | 批准的只读端点、有效模拟身份、矩阵期望 ALLOW，夹具响应符合契约 | 通过 Controller 请求本地 API | ALLOW／EXECUTED／PASS；有真实请求响应证据，派发数为 1。 |
| GWT-P02 Positive | 正确权限模式，参数化为未认证、他人对象、低角色三类；各自有合法访问对照 | 发送获准的负向请求并检查关联对照 | API 按契约拒绝且无泄露，对照成功；负向用例为 ALLOW／EXECUTED／PASS。每个请求单独计检查。 |
| GWT-P03 Positive | 可写证据位置，模拟 Token，两个同秒启动的运行 | 执行允许及拒绝检查并生成记录 | ID 唯一不覆盖，事件可关联，拒绝原因可查；无原始 Token；模拟数据明确标识。 |
| GWT-P04 Positive | 相同版本的契约、矩阵、重置夹具、策略和预算 | 两次规则规划并按文档入口使用；核对比较元数据 | 计划一致、输入可复现，记录候选、版本、预算、请求数与覆盖；不声称已完成策略比较。 |
| GWT-P05 Positive／工程实验 | 基础闭环完成；两种确定性策略，同一输入、候选、声明目标、授权、重置夹具、预算和环境 | 按 C-02 独立重复运行并比较 | 两者遵守 Controller 边界；报告七项课程指标、分子分母、三种计数和规划开销，保留负结果；ADR 给出采用／限制采用／保留固定／需要更多证据，不预设动态更优；REQ-020／021 均 MUST，未执行不得宣称完整交付。 |
| GWT-N01 Negative | 契约缺失、矩阵矛盾、授权缺失或初始计划 9 项之一 | 请求启动 | 不发请求，STOPPED/INVALID_INPUT，明确原因；不得擅自补授权或裁剪计划。 |
| GWT-N02 Negative | 已知缺陷模式，参数化为匿名泄露、他人对象泄露、低角色泄露 | 发送批准的只读请求 | ALLOW／EXECUTED／FAIL，并保留能确认泄露的证据；另以预期 ALLOW 却确认被错误拒绝的变体验证过度拒绝 FAIL。 |
| GWT-N03 Negative | 输入为畸形 JSON、数组、null、错误字段类型、缺字段、未知字段或越界身份参数之一 | 提交 Controller | DENY／NOT_EXECUTED／INCONCLUSIVE，不崩溃、不派发，记录原因并计入尝试数。 |
| GWT-N04 Negative | 初始登记 6 项；追加 2 项；或累计登记 8 项后在 RUNNING／终态分别提交新提案；包含拒绝及重复提交变体 | 登记、校验、派发并判定终态 | 共用累计额度，登记与尝试分开计；第 8 项可执行，RUNNING 的超限追加不计为第 9 项且 STOPPED/BUDGET_EXHAUSTED；无待决追加且到点前处理完为 COMPLETED；终态追加不重开。满足 request_count <= attempt_count <= plan_count <= 8。 |
| GWT-N05 Negative | 静态预检后首次规划前 t0=0；可控单调时钟；分别测试初始规划到 90 秒、规划 30 秒后等待到 90 秒、最后一项恰在 90 秒处理完及日期回拨 | 规划、派发、等待并检查时间／完成状态 | 规划计入预算且 t0 不重置；规划耗尽时派发 0；elapsed >= 90 秒均预算停止，禁止新派发并取消／超时在途；恰到点完成不得记 COMPLETED，90 秒前完成才可；日期回拨不扩预算，并发 <= 1。 |
| GWT-N06 Negative | 参数化为连接失败、HTTP 5xx、非预期 JSON、审计存储不可写、执行异常 | 运行批准检查 | 按第 7 节停止，记录准确执行状态和缺口；不自动重试，不产生虚构成功或完整证据声明。 |
| GWT-N07 Negative | Controller 拒绝、对照不成立、判定所需响应截断／缺失之一，且无可确认违例证据 | 生成结论和报告 | 受影响用例 INCONCLUSIVE；不能把 EXECUTED 或拒绝等同于 PASS；列出限制和未覆盖范围。 |
| GWT-A01 Adversarial | 响应含扩权指令或 Planner 提议修改政策；另含无新增有效证据而重复提案的变体 | 处理响应并请求继续 | 授权、预算及结论标准不变；越界意图拒绝且无派发，不能绕过入口；仅满足第 4 节第 9 项全部条件的无价值重复循环才 STOPPED/NO_NEW_EVIDENCE；剩余有价值检查或必要对照仍须继续，见 GWT-A01-a～c。 |
| GWT-A02 Adversarial | 提案包含外部 origin、未批准端点、写方法、歧义路径、替换身份或响应重定向之一 | 请求执行或收到重定向 | 不派发越界请求、不自动跟随；记录拒绝或未决原因，凭据不转发到其他目标。 |
| GWT-A03 Adversarial | 最终派发前或存在在途请求时收到可信撤权 | Controller 处理撤权并尝试后续派发 | 撤权生效后新增派发为 0，尝试取消在途；记录停止、在途事实和未决项，不伪称已发送请求被撤回。 |
| GWT-A04 Adversarial／后续 | 另行批准的真实 LLM 接入已存在 | 模型提出越界请求 | Controller 同样拒绝，原边界及预算不变；成本来自真实计量且与模拟数据区分。 |

### GWT-A01 的无新增证据正反例（均未执行）

以下变体关联 P3-REQ-010、014、017；沿用现有组 ID，仅增加子场景。各变体均先满足原授权、预算和撤权规则。

| ID／类别 | Given | When | Then |
| --- | --- | --- | --- |
| GWT-A01-a／应停止的正例 | RUNNING 的待决继续提案只是重复已处理内容，无新增有效证据；已核对批准计划／候选，没有有价值的未执行检查、必要对照或在途检查；尚未进入终态 | Planner 再次请求无价值的重复规划／继续循环 | STOPPED/NO_NEW_EVIDENCE，不派发重复请求；记录重复与剩余范围核对依据，保留结论及未覆盖，计数不因停止重置。若原本已满足正常完成条件且无待决提案，则应 COMPLETED。 |
| GWT-A01-b／防提前停止的反例 | 一项检查未发现漏洞或按契约拒绝；仍有另一身份／对象的批准未执行检查，按计划可提供新覆盖，授权有效且预算剩余 | Planner 因“没发现漏洞”请求停止或重复上一项 | 不得以 NO_NEW_EVIDENCE 提前停止或跳过剩余检查；拒绝无价值重复，继续既定有价值检查。即使下一项返回同样状态码，也按独立身份／对象证据判定，不据状态码重复误停。 |
| GWT-A01-c／必要对照的反例 | 负向请求收到403／404但尚无充分合法访问对照；计划中批准的所有者／合法角色对照未执行，授权有效且预算剩余 | 处理负向响应并决定是否继续 | 不得因无漏洞或表面拒绝触发 NO_NEW_EVIDENCE；先执行必要对照，再按完整证据判定，未有充分证据前不得记 PASS。若此时撤权或预算到点，按原 REVOKED／BUDGET_EXHAUSTED 停止，不为完成对照突破边界。 |
