# 架构决策与 HTTP 接入设计阶段总结

整理日期：2026-10-26。设计成果随需求及实现迭代形成，主要历史节点为 `48dd5f8`、`e09ca38`、`74ed7b1`；不把交叠的设计工作强行定义为独立课程编号阶段。

## 1. 目标与范围

把规划建议、可信授权、执行派发及证据判定分离，在不发送 HTTP 的条件下定义可实施的接入契约。复用现有 Controller，不建立由 Planner 自行授予许可的通道。

## 2. 主要成果

ADR-001 保留 Planner／Controller 分离的历史决策；ADR-002 比较黑盒与白盒并选择契约驱动的黑盒路线；ADR-003 接受 Python 标准库、可信本地配置、JSONL／Manifest 和 CLI；ADR-004 接受分离派发状态机与单 I/O 所有者。技术方案 Accepted 不等于目标执行授权。当前仍为同进程模块边界，不能声称已完成物理隔离。

HTTP 契约限定三个 GET 端点、六项候选及合法访问对照，设计 Good 与独立 AUTH／BOLA／RBAC 缺陷夹具。登记需要实际批准来源、范围及版本绑定；执行禁止代理、重定向和自动重试。

设计将 connect、首次正字节发送、部分发送、撤权与计数的先后关系显式化，避免把阻塞 I/O 放在长锁内。已发送字节不可撤回。异常长度、非法 JSON、截断和证据不足时保持 INCONCLUSIVE，不能凭 canary 子串确认 FAIL。

## 3. 验证与证据

HTTP 设计审核报告记录了授权登记、发送竞争边界和异常响应规则的修订；该轮仅静态设计，没有启动服务或运行 HTTP 集成测试。报告引用的此前 49 项离线测试属于既有实现背景，不是本设计的执行验收。后续实现及测试另见阶段覆盖表。

ADR 和设计报告可证明决策内容与变更背景，不能证明网络取消、OS 调度或许可来源真实性。本次未开展新的测试或独立代码复核。

## 4. 问题、限制与下一步

在途请求不能立即无条件取消；迟到结果、资源关闭失败与审计缺口均需保守处理。容量建议仍需实验，不能当成教师冻结值。ADR-005 的策略推荐继续为 Proposed，不因本次整理改变状态。

设计已提供离线工程实现依据。下一步真实集成必须先落实目标许可、教师目录及运行绑定，并验证操作系统层面的发送、撤权和清理；当前 14 项真实验收均待授权。
