## 1. 使用规则

1. **状态值**：`已完成`、`部分完成`、`缺失`、`待确认`、`外部依赖`。同一事项若多维度状态不同，分行登记，不合并为「已完成」。
2. **不得由文档补录替代真实动作**：真人审查、复核、签署、教师审批只能由真实主体完成；AI 与项目负责人不得代签、不得生成虚构记录。
3. **不虚化石前记录**：事后整理的材料只能标为「事后整理」，不得改写成事前计划、事前约定或事前实验卡。
4. **缺口ID 稳定**：一经分配不重排；关闭缺口时保留行并追加关闭依据，不删除历史。
5. **真实 HTTP 不作为当前离线交付的 P0 阻断项**：依据见 §5.3 的课程附录H H4。

**GAP-005 状态说明（提交前／提交后须区分）**

1. 课程回执属于**实际提交完成之后**才产生的核验材料，不是提交前的准备物。
2. 当前尚未提交，因此没有回执属于**正常的待完成状态**，不是材料造假或流程倒置。
3. 该缺口**不阻止候选交付包的整理与内部复核**；本表其他条目（真人复核、伙伴复现、签署）才是提交前的实质前置。
4. 正式提交完成后，必须保存**实际取得的回执**（平台链接或截图，含日期与提交对象）。
5. 没有真实回执时，一律不得宣称「课程提交成功」「已提交教师」或「作业已交」。

据此，GAP-005 列为 P0 的含义是：**课程提交状态尚未闭环**，而不是「必须先拿到回执才能开始整理与提交」。提交动作本身由项目负责人按教师要求执行；本表只登记状态。

## 5. 关键边界说明

### 5.1 真人参与不可替代

GAP-001／002／003／004／005／030 涉及真实第二人或教师。这些缺口**不能通过文档补录、AI 生成或负责人代签关闭**。若真实人员无法参与，正确做法是如实保留 `缺失` 状态，不得降低标准。

### 5.2 历史实验与成本

- 执行版本 `NOT_FULLY_BOUND`：归档提交 `9754048` 与 `3199b3f` 等仅为定位线索，不是执行版本。
- 事前实验卡：**只能登记为「事前未形成或未发现」**，不得事后补录为事前记录（GAP-007）。
- 人工成本 `NOT_MEASURED`：符合课程「未知不填零」要求，但影响「成本范围」维度的完整度（GAP-008）。
- 统计证据：每格 3 次重复，仅支持「暂时保留 Fixed」的保守工程取舍（GAP-009）。

### 5.3 真实 HTTP 与附录H 止损规则

课程 S3 第 119 张（物理第 117 张）附录H H4 原文：「本学期止损方式：P1/P2 优先成熟；P4 未过理解门先补课或改题；**P3 停在模拟器**；P5 无可恢复快照则不正式开放；评价 Agent 若增加核验负担，减少自由工具和覆盖范围。」

据此：

1. P3 的课程定位本身即**停在模拟器**，14 项真实 HTTP `PENDING_AUTHORIZATION` **不作为当前离线交付的 P0 阻断项**。
2. 该规则是否构成正式豁免、以及是否需按治理 A-05 申请具体 `NOT_APPLICABLE`，仍属**教师确认范围**，本项目不自行认定。
3. 独立 OS 未派发证明 `UNAVAILABLE` 保持登记，不因止损规则而消失。
