# 需求规格与工程治理阶段总结

整理日期：2026-10-26。历史范围：2026-10-12 至 10-14，代表提交 `48dd5f8`、`937c102`、`e09ca38`。这是按已有成果组织的工程阶段，不是新认定的课程阶段编号。

## 1. 目标与范围

将早期授权拦截演示原型调整为面向软件验收的黑盒授权安全测试 Agent。明确目标、合法对照、授权责任与验收标准，使“Controller 是否允许执行”和“API 权限控制是否正确”成为不同判断。V1 限定获准的本地隔离 HTTP JSON API，不引入公网扫描或真实账号。

## 2. 主要成果

Problem Frame、授权边界、22 项稳定需求与 GWT 已形成相互关联的候选基线。RC1 原文保留，当前工程候选为 V1.0-RC2。治理将事项区分为课程明确审批、负责人技术决策、需实验验证三类，教师事项按执行、冻结、验收及教学评分阶段分别约束。

RC2 明确累计登记、首次尝试、实际请求三个计数，初始计划与追加共用预算；90 秒从静态预检后、首次规划前开始。8 项、90 秒、并发 1 仍为试跑参数。NO_NEW_EVIDENCE 不得跳过有价值的批准检查及必要对照。固定／动态策略比较 REQ-021 为 MUST，真实 LLM 不作为首版必需条件。

## 3. 验证与证据

本阶段交付是规格、治理与场景定义，没有对应的运行测试通过数量。上述提交可在本地 Git 历史定位；RC2 的版本记录与治理表保留修改依据。GWT 文档说明待验证行为，不能充当执行日志。后续自动测试结果不倒填为本阶段已完成的功能验收。

本次仅核对文档与历史，没有重新执行测试，也未取得独立课程验收签署。

## 4. 问题、限制与下一步

历史 MAY 与预算计时、追加计数、停止语义的歧义已在 RC2 修订；保留历史版本以供追溯。工程文档批准不构成目标许可。实际目标所有者／受托者许可、教师批准目录、预算冻结与正式课程验收应按各自流程核验，不能以配置字段代替材料。

规格阶段已具备工程开发依据；正式课程阶段名称与本总结的映射仍待确认。后续实现须继续追踪稳定需求，并以真实结果支持有限结论。
