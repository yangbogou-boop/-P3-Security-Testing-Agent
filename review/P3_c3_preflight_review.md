## 先复现，再最小修复

基线回归 `test_revoke_between_final_check_and_send_blocks_response` 使用假 TCPServer 捕获 Handler、假连接和确定性钩子，在最后授权检查之后、`sendall()` 之前使撤权生效。旧实现失败：`writes=1`，期望 0。保存修复前失败日志；没有创建 socket 或启动监听器。

根因是最终检查和阻塞 sendall 分离。把整个 sendall 放入撤权锁会阻塞撤权，与 ADR-004 冲突，因此没有采用。实际修复沿用已接受方案 B：单 I/O 所有者、非阻塞 socket、分段发送和短 gate，不引入新架构或改变 ADR 状态。

服务端变化：

- 抽出 `_handle_connection`，Handler 委托该方法。每次连接使用非阻塞模式；读取／可写等待在 gate 外，最长一次 readiness 等待 10 ms（不是硬实时承诺）。
- 每次 `send` 的最终授权／绑定／截止检查、一次非阻塞调用及偏移记录在同一个 gate 内。撤权的生效点为同一 gate 内置位、递增序号；请求到达时间在获取 gate 前采样，生效时间和序号单列。
- 撤权先赢：本次及后续发送都被拒绝。send 先赢：已经返回正数的字节保留，之后获得 gate 生效的撤权阻止续写。请求到达不等于生效；不能宣称已提交内核的字节可撤回。
- 部分发送只沿同一连接的剩余偏移推进；BlockingIOError 返回等待，不重连或重发完整响应。超时／异常停止，保留已发字节，I/O 所有者在 gate 外关闭。
- 服务许可缺失失败关闭；增加单调许可截止，墙钟回拨不延长有效期；实例、范围和生成凭据绑定仍全部复核。服务单连接处理 2 秒是既有试跑上限，不更改 Agent 的 RC2 总预算。
- 清理失败记录为显式标志，阻止后续服务发送；监听器 close 失败也显式报告。socketserver 结束路径只作幂等 close 兜底，不再执行默认 shutdown 写路径。不能由单元测试推断 OS 已释放句柄。
- `last_connection` 是仅包含固定原因码、字节数、连接 ID、序号与撤权时间的有限快照，无原始参数／凭据／异常正文。后续监督者必须及时关联保存它；本轮没有把该内存摘要宣称为持久化 Evidence。

服务端响应字节不进入 Agent request_count。客户端 live／machine／protocol／audit 实现此次均未改动；原首次正发送、部分发送、预算和不可重开终态语义保持不变。
