# ADR 003：本地模拟执行、证据组织与工程试跑方案

日期：2026-10-12。

## Status

**Accepted／项目负责人于 2026-10-14 第三阶段第一轮确认技术方案**：Python 标准库、可信本地配置、JSONL 事件与 Manifest、CLI。确认不等于运行测试授权、教师审批或功能验收；证据容量上限与实验结论仍未确认。历史状态：2026-10-12 提案及 RC2 文档修订时均为 Proposed。课程审批事项仅按 [治理登记](../brief/P3_decision_governance.md) A 类处理；已有黑盒方向与已审核计数规则不重新等待教师批准。

当前候选规格：[Specification V1.0-RC2](../brief/P3_specification_v1.0-rc2.md)，2026-10-14 同步引用；本次 Accepted 来自项目负责人明确开发指令，不是因 RC2 版本升级自动接受。

## Context

当前只有模拟扫描意图和结果，没有 HTTP Executor、可响应的模拟 API 或完整审计链。要在已有 HTTP JSON、模拟 Bearer Token、只读及强制 Controller 入口约束下形成可复现的最小闭环。课程要求先纯模拟流程再开放教师批准的本地动作；模块分离不能宣称物理隔离。

## Alternatives

| 方案 | 需求／复杂度 | 安全／成本／可复现与维护 |
| --- | --- | --- |
| 标准库 HTTPServer、HTTP 客户端、JSON 配置和文件证据 | 足够承载少量只读端点，无新增依赖 | 零外部服务费用、容易离线重置；路由校验、超时及取消边界需自行实现，不能用于宣称生产级服务。 |
| FastAPI／Flask 与外部 HTTP 客户端 | 声明式路由／验证与更成熟组件 | 多依赖及版本管理，当前小范围收益未测；端点规模或契约复杂度增长时值得重评。 |
| 数据库与完整平台／GUI | 查询和交互能力更强 | 引入迁移、权限、部署与维护负担，不是首版闭环必需。 |
| 容器／独立进程执行 | 可增强操作系统边界 | 环境准备成本较高；容器名不证明隔离，宿主挂载与 Docker socket 可能破坏边界。真实或不可信工具出现时须单独设计。 |
| 仅伪造成功消息 | 开发最少 | 无实际 HTTP 与权限证据，不能满足 REQ-013，排除。 |

## Decision

技术路线采用 Python 标准库；后续 HTTP 切片拟用标准库 HTTPServer 承载回环地址模拟 API，配置化模拟身份、角色、对象及 Good／Known Bad 夹具；命令行加载可信契约、权限矩阵和授权配置。标准库 HTTP 客户端仅由 Controller 强制入口派发已登记请求，不接受任意 URL／Shell，禁止代理、重定向和原始 Token 日志。

先提供纯模拟响应路径以验证状态、预算和撤权，再在 A-01 目录批准及目标授权齐备后开放本地 HTTP。Controller 绑定不可由 Planner 修改的政策快照，可信撤权入口只减权。具体运行机制的竞态与取消延迟必须测量；同步请求不承诺瞬时取消。

采用每个 run 独立目录：JSONL 事件、JSON Manifest 和有限报告，使用唯一 run／check／attempt／evidence ID。保留既有 evidence 原样，禁止同秒覆盖；记录拒绝、错误、停止、实际请求与未覆盖，脱敏并说明截断。这是产品内部格式，不能替代教师冻结的评价输出 Schema。

按治理登记 C-01～04 进行预算、策略及证据试跑。8／90／1 保持教学试跑属性；证据片段 64 KiB／run 1 MiB 为新工程建议，未确认且未测，不作为已生效限制。最终班级预算由教师试跑后冻结。

## Rationale

优先满足受控执行、可判定权限、可复现证据和低维护成本。标准库小切片可以使所有依赖与数据留在本地，减少非核心平台工作；确定性策略允许直接比较检查收益和规划成本，不需要付费 LLM。实验记录必须报告覆盖与成本，不能把少做任务直接包装成效率优势。

## Consequences

- 收益是依赖少、无商业服务成本、夹具易重置和证据易检索；这些是工程理由，尚未有性能实验数据。
- 代价是自行维护字段验证、协议错误处理、证据关联和同步请求取消边界；模块设计不能防任意同进程恶意代码。
- 存储／超时失败时先安全停止并报告不足；保留有限结论，不用模拟成本或消息代替实际结果。
- 框架及格式已由负责人确认，当前实施只限离线核心；正式课程合同、目录、预算及评分权限仍按 A 类，不以 Accepted 工程 ADR 绕过。

## Reconsideration

契约变复杂、标准库代码难维护、复现或停止试跑失败、必要证据经常被截断时重评框架与证据方案；动态无同目标质量／成本收益时保留固定 Baseline。接入实际系统或第三方不可信工具、需要进程权限隔离时重新评估架构并取得授权，不自动扩大当前范围。接受条件及逐次试跑设计见治理登记 C 类；未有数据不得宣称任何替代方案更优。


## 2026-10-14 实施边界与重要取舍

- 当前只新增 `src/p3_core/` 离线包，旧 `src/main.py`、`src/planner/`、`src/controller/` 保留历史状态。CLI 不调用旧演示，不构造 HTTP 客户端、服务器或真实 LLM。
- 固定 Planner 接收不可变候选集合；Controller 从可信入口复制并校验配置，冻结为数据模型，自行比对端点、方法、身份、精确参数组合、权限预期及候选身份。拒绝依赖自然语言“已授权”声明；模块边界不是任意 Python 代码隔离。
- 备选方案包括把假派发计成 HTTP 请求、伪造响应完成判定，均排除。采用 `request_count=0` 与单独 `offline_dispatch_count`，假派发后的执行状态仍 NOT_EXECUTED、API 结论仍 INCONCLUSIVE；测试通过只证明控制逻辑，不证明 API 权限正确。
- 同步、非阻塞内存派发器与串行锁适合本轮离线测试；可信撤权入口与假派发接纳在同一锁上确定先后。重入派发拒绝。阻塞网络调用不能直接套用该锁：下一轮必须先设计可取消派发边界并测试撤权竞态／取消延迟。
- 无新增证据检查保守地把所有尚未处理的批准候选视为有价值或价值未知；重复继续请求不能跳过它们或必要对照。正常固定计划完成仍可 COMPLETED，未选择候选如实列为未覆盖。当前不实现响应评价或动态策略比较。
- 审计事件在决定及假派发前写入，写入失败会在运行中 STOPPED/AUDIT_ERROR；同检查点仍按撤权、授权失效、运行错误、预算顺序处理。终态收尾文件失败时不修改已冻结终态，另报 `audit_gap=true`、`audit_error=AUDIT_ERROR`，CLI 返回 3 并禁止新动作。该区分保留终态不变量，不把缺失记录当成完整证据。
- 每 run 使用 UUID 独立目录，独占创建报告和 Manifest，Manifest 最后写入；缺失或无法解析 Manifest 视为收尾不完整。Manifest 保存事件前缀字节数及 SHA-256；后续终态拒绝可追加事件，但不改写先前快照。无操作系统防篡改／断电持久性保证，文件校验不等于数字签名。
- 不加载原始凭据，配置和计划只接受身份引用；对可信入口显式提供的模拟敏感值统一脱敏，不持久化任意畸形提案正文或异常原文。真实凭据解析和响应截断留待 HTTP 切片，不宣称已通过 C-03 容量实验。

评价标准是 RC2 状态／预算不变量、无网络、无虚构 API 结论、可重现与维护成本；代价是实际请求、取消、HTTP 错误、响应断言及业务结论仍未实现。离线测试结果见 [第三阶段第一轮验证记录](../eval/P3_offline_core_validation.md)，不替代课程验收、A 类审批或 C 类正式实验。若需要阻塞执行、真实响应、大型注册表、跨进程或防篡改证据，应按 Reconsideration 重评。
