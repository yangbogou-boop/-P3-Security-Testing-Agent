# ADR-004：HTTP 派发边界与在途撤权

**当前 Status：Accepted（2026-10-19）**。项目负责人在第三阶段第二轮 B 指令中明确确认“分离派发状态机 + 单 I/O 所有者”。确认范围为技术路线及本轮无网络实现，不是实际目标授权、教师目录批准或功能验收。下面保留 2026-10-14／19 审核前 Proposed 原文，历史“尚未 Accepted”不代表当前状态。

修订：2026-10-19，仅澄清竞争边界、授权登记和异常响应；未实现或执行新测试。

日期：2026-10-14。Status：**Proposed**。等待项目负责人审核技术取舍；不是运行授权、教师批准或验收完成记录。

## Context

[ADR-003](ADR_003_local_execution_and_evidence.md) 已接受 Python 标准库路线。当前 Controller 和可信撤权 gate 在锁内调用非阻塞假派发器；直接替换成阻塞 HTTP 会使撤权入口等待网络。HTTP 接入还需保证 RC2 的累计计数、并发 1、最终派发前复核、不可重开终态，以及诚实记录已发送且无法撤回的请求。

本 ADR 不修改 [RC2](../brief/P3_specification_v1.0-rc2.md)，不替代 [授权登记草案](../brief/P3_http_contract_draft.md)。详细协议和故障判定见 [接入设计](P3_http_integration_design.md)。

## Alternatives

| 方案 | 优点 | 代价／风险 |
| --- | --- | --- |
| A：单工作线程、阻塞 HTTP 客户端，锁外执行 | 实现较简单，标准客户端成熟；撤权可以先置位 | 无法强杀线程；调用内部的 connect/send 不易与短门同步；检查后再调用存在竞态，整次加锁则阻塞撤权；跨线程关闭需实验 |
| B：分离状态机、单 I/O 所有者、非阻塞 socket/selectors | 每次发送与撤权共享短门；等待不持锁；可观察部分发送与计数边界 | 必须处理连接、部分写、响应 framing、事件交接及清理，测试复杂度增加；不是硬实时系统 |
| C：子进程执行器 | 可以终止进程并回收句柄，降低失联线程风险 | IPC 与崩溃后发送事实难确认；不能撤回已发请求；当前规模下维护成本高 |

评价标准：撤权后新派发为零、累计计数可验证、证据诚实、失败关闭、可复现性、实现与维护成本。三种方案均不能承诺撤回已发送字节。

## Decision

**建议采用 B，尚未 Accepted。** 保留标准库和离线模式；HTTP 使用专用单 I/O 所有者推进状态机，响应解析限定到契约所需 HTTP/1.1 子集。应用强制入口不宣称是操作系统沙箱。

Executor 只接收 Controller 登记的一次性不可变执行对象。真实目标固定为授权登记的 IPv4 回环字面量与端口，不使用环境代理、不跟随重定向、不重连或自动重试。有限参数从同一规范对象生成请求，不另行解释 Planner URL。

撤权入口和非阻塞发送共用短 gate，锁内不做磁盘写入、阻塞网络、等待或任意回调。每次 connect/write 前核验有效授权、generation、终态、截止与审计健康。撤权只需短 gate 即可置位和唤醒 I/O，不等待 Controller 主锁或线程退出。

建议将 RC2 的实际 HTTP 派发落在该 action 首次 send 返回正字节数，原子更新内存 request_count 和一次性消费标志。这只是待审核的实现微边界，不改变累计预算定义；连接成功、ALLOW、入队与离线假派发均不计请求。部分请求仍计 1，剩余字节只能沿原连接／偏移发送；撤权后不得继续写。

网络和持久化无法原子提交。发送后崩溃或审计失败必须暴露缺口，不重试、不声称未发送。终态冻结，迟到响应只追加观察，不能使未完成检查升级 PASS。

## Rationale

B 将危险的长等待移出撤权关键区，并把“是否已发送”作为可测试事实。相较 A，其复杂度主要集中在小范围传输状态机，可以用可注入时钟、假 socket 与事件顺序离线验证；相较 C，无需新增进程协议。对低并发、只读、有限契约的本地夹具，这一代价可以接受，但须先验证后实现结论。

## Consequences

- 后续需要拆分现有同步接口，保持离线 49 项回归及重复 ID、最小化审计修复；本轮不实施。
- 不支持通用 HTTP 功能：无代理、redirect、retry、压缩、chunked、连接池；扩展须重新评审契约和攻击面。
- Python 调度和短系统调用不提供硬实时截止；必须测量取消生效和资源回收延迟，不声称线程可立即终止。
- loopback 不证明进程身份；可信管理器绑定实例和生命周期。宿主被攻击或需抵御任意同进程代码时，当前边界不足。
- API 结论依赖完整断言与合法对照，执行成功不能直接 PASS。64 KiB／1 MiB 容量只是实验建议。

## Reconsideration

离线先按 [验收计划](../eval/P3_http_acceptance_plan.md) 验证发送／撤权所有顺序、计数不变量、部分写、审计故障与终态；实际许可齐备后，每个获准竞态／故障变体至少 3 次独立重置试跑，报告样本数及全部失败，不宣称统计优势。

接受硬条件：未授权及撤权生效后新派发为 0；每检查最多一次请求；并发不超过 1；计数和证据一致；原始模拟凭据零落盘；迟到结果不升级未完成结论。取消延迟、内存／存储上限由负责人在实验卡中预先确定，未确定不得宣称性能达标。

若窄协议不足、状态机无法稳定复现、资源未回收、撤权延迟超实验条件、宿主隔离要求扩大，或维护成本明显超过方案 A/C，重新比较并记录结果。安全硬条件失败立即停试，不放宽授权或通过重试掩盖。

## 2026-10-19 审核澄清（Status 仍 Proposed）

不改变方案 B。connect 的最终检查、一次非阻塞调用及返回登记同属短 gate；连接不计 HTTP 请求，完成后首写重新核验。首个正字节 send 与内存 dispatch_started／offset／request_count 更新在释放 gate 前完成；续写限定原 action 和偏移，不因一次性标志阻止合法剩余字节，也不重复计数。撤权的线性化点是门内置位及 generation 更新，调用到达与生效分记；已提交内核的字节不可撤回。原子性不覆盖进程崩溃或网络与磁盘，缺口不得伪造计数。确定性竞争验收见 HTTP-T27～T31。

授权采用契约 §7.1 的最小人工核验流程：真实目标许可＋教师目录材料、指定可信核验者、范围交集核对、受宿主写权限保护的只读版本快照、最终派发复核与本地撤权入口。摘要检测变更，不证明批准真实性；不引入额外签名系统，不以 approved_by／active=true 替代材料。

异常响应统一按接入设计 §6.1：framing、完整 JSON、来源关联、断言与持久化是确认的必要条件。重复／冲突长度、非法 JSON、超长或截断中的偶然 canary 不能新增 FAIL；当前证据不足则 INCONCLUSIVE，按 RC2 记录真实停止原因。仅完整充分的 5xx 泄露证据允许 FAIL 与 RESPONSE_ERROR 并存；其他检查的既有 FAIL 不受影响。

## Accepted 承接与本轮实现限制（2026-10-19）

采用方案 B；新增 `p3_core.http`，不把阻塞调用塞入旧 Controller。原 offline 核心原样保留，独立 `SimulationRun` 实现同样的累计登记／尝试、停止与撤权规则；单 I/O 所有者推进内存传输的一个步骤，可信撤权仅获取短 gate。两条路径通过回归分别验证，尚未合并为真实 HTTP Controller。

本轮 `request_count=0`；`model_request_count` 是内存假 send 首次返回正数的模型计数，与实际请求明确分列。`execution=NOT_EXECUTED`、API `conclusion=INCONCLUSIVE`；纯判定器只输出带 NO_NETWORK_SIMULATION 来源的 `simulated_conclusion`。这不修改 RC2 三计数含义。

首版配置使用版本化六项有限候选；材料核验接口接受可信操作者提供的已核验材料与同一份登记字节。范围摘要必须精确匹配，宽泛原许可由人工先形成共同范围的核验记录，不由程序自动扩展或解析自然语言批准。哈希不证明身份；宿主权限、真实材料取得、外部撤销传达仍由可信操作流程负责。

只提供 MemoryTransport；没有 socket、selector 驱动、HTTP 服务或真实执行入口。保持标准库路线，未来经许可接入真实 I/O 仍需审核字节发送／资源回收和线程调度边界。新增代码不意味着真实取消延迟、容量试跑、课程验收或 REQ-021 策略比较已完成。验证及风险见 [第二轮 B 审核报告](../review/P3_http_offline_core_review.md)。
